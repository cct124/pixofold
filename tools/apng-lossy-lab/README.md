# APNG共享调色板有损实验

显式开发特性apng-lossy-lab，经pixofold_core::apng::lossy_lab提供内存候选与独立比较；底层validation/quantization与[单文件生产核心](../../crates/pixofold-core/src/apng/README.md)复用。生产显式有损使用固定alpha_palette/无抖动、质量/收益无损回退和共享输出层；批量与桌面v13继续冻结无损。本实验入口没有生产文件提交、批量服务或IPC权限，也不随MSI分发。

## 运行与产物

```powershell
pnpm apng:lossy:check
cargo test -p pixofold-core --features apng-lossy-lab --locked --lib apng::validation::quantization
```

脚本使用锁定的imagequant 4.4.1、png 0.18.1、fdeflate 0.3.7和oxipng 10.2.1，不新增依赖。两编码器均关闭默认并行特性。每次建立新的target/apng-lossy-*目录，复制原件、来源与许可；核对语料/来源清单与隔离输入SHA256，每次调用后复查隔离源。CLI只读输入，输出独占创建；质量或收益被淘汰的候选仍保留供审阅，硬错误、取消与超时不产生可接纳结果。

- report.json：全部样本、无损基线、候选、拒绝原因、逐帧/时间误差、质量筛选、资源及取消证据。
- comparison.html：原件/无损/有损候选对照，切换黑白或棋盘背景及不同质量/抖动候选。浏览器动画不保证同步；视觉验收和数值验证分开。
- engine-identity.json：源码配方、Cargo.lock、两示例二进制SHA256、feature、编译器、平台、HEAD与工作树状态。
- inputs/outputs/baselines：全部隔离输入与实际候选。无损有效基线取原件与经验证O1候选中较小者，较大O1候选仍保留。

v2矩阵包含既有83项确定性语料、6份公开原件、13项合成样本及3份真实PNG衍生动画，共105输入。50个支持输入各运行质量0/50/80/95/100、抖动关/开及三种映射策略，55项结构/额度/颜色边界按固定原因拒绝，共1,555组；另测执行中取消与1ms软期限。新场景包含全alpha梯度、稀有端点与24帧连续OVER；衍生动画来自已许可的透明骰子、Pillow透明图片及棕褐色照片，source-png保存原件，derived-sources.json记录作者、许可、源/衍生哈希和构造参数。192×144采样及平移是输入构造，不算压缩收益。

意外硬错误会使命令失败，质量筛选失败是保留的实验结论。分组策略的全部候选还须经实际字节验证原始alpha分类不变、差≤4（q100为0）、无缺失色表项；至少一份真实图片衍生动画在q≥80获得质量/额外收益通过。执行结束复查仓库原件与隔离源；源检查失败同样保留失败报告。

## 编码与支持边界

第一遍逐帧严格zlib/原始及展开双解码，最多累计65,536个位置采样。每个子帧和独立默认图公平分配样本名额，按像素位置分层采样，小帧剩余名额不转移。只保留有界样本、统计与当前帧，不缓存全部帧。第二遍全量重映射，每帧使用同一冻结RGBA色表（至多256项），写8位索引PLTE/tRNS。speed=4，抖动分别为0和1。

| remapping             | 实验策略                                                                                                                                |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| standard              | 原v1普通共享Histogram与imagequant重映射，用作对照                                                                                       |
| alpha_constrained     | 保留普通色表和合法索引；仅对跨透明分类或alpha差>8的像素搜索可行颜色，q100要求alpha精确；无可行项则记录质量拒绝                          |
| alpha_palette（默认） | 按实际alpha分组构建共享色表后再约束索引；透明0、不透明255独立，部分透明每8级一组，中心取全量均值并限制原始差≤4；q100按每个alpha精确分组 |

分组路径遍历全部源像素，统计每组面积、alpha范围和RGB均值。采样漏掉的非空组补一个全量统计代表色（最多256项，报告representativeSamples单列并计费）；所有组至少一色。剩余色表预算按面积、采样颜色数和可见alpha加权分配，确定性排序，RGB分别量化后组成一张全局色表，最终颜色总数≤256。面积权重避免稀少抗锯齿像素挤占主体颜色。固定色表直方图以目标100冻结最终条目，不代表候选质量100；请求质量仍作用于组内量化和所有验证门槛。

约束重映射保留合法的抖动索引，只替换违规项，不将alpha误差再扩散给邻居；候选色以锁定imagequant距离公式比较。缓存是4,096槽直接映射表，颜色键必须完整匹配，碰撞覆盖不改变结果；所有条目检查受独立预算约束。修正不会重跑误差扩散，因此实际抖动像素仍须重新评分。无可行条目保留诊断候选并报告alpha_palette_unavailable，不能伪装为通过或无损回退。

首版支持8位非交错灰度/RGB/灰度透明/RGBA及索引输入的安全展开。16位、Adam7和低位深明确拒绝，不暗中降深/改交错。接受未声明颜色、sRGB及0<gAMA<1；sRGB并存时gAMA必须45455。cHRM、ICC、Exif、保护及未知元数据拒绝，不剥离后继续。初始支持范围比生产严格无损更窄。

只改变像素与色型/色表。画布、子帧尺寸和偏移、SOURCE/OVER、NONE/BACKGROUND/PREVIOUS、原始延时分数、num_plays、默认图是否参与保持不变。原数据块可重新分片并连续重编号；gAMA/sRGB/pHYs/tEXt保持内容、顺序及动画锚点。默认静态图参与共享色表，但独立默认图不进入动画画布。

## 独立验证与实验筛选v2

候选按实际字节重新解析、校验CRC/zlib及索引，再独立双解码/合成RGBA16画布。硬语义错误返回失败，不能当作质量不足或无损回退。验证覆盖原始子帧alpha、默认图、显示画布、可重播时第二轮透明画布及跨循环相邻显示误差；有限单次播放只验一轮。

| 筛选项                    | 暂定条件                                               |
| ------------------------- | ------------------------------------------------------ |
| 逐帧重映射评分            | 所有帧（含独立默认图）的最低评分至少为请求质量q        |
| 透明分类                  | 0、部分透明、255三个类别不得改变                       |
| alpha误差                 | 8位等效单位最大差≤8；q100为0；原始子帧与合成画布均检查 |
| 黑/白背景整体RMSE         | ≤L，其中L=(100-q)×0.2                                  |
| 任一显示帧RMSE            | ≤1.5L，避免全局平均掩盖低质量帧                        |
| 时域误差RMS及最差相邻变化 | ≤2L；误差相同的重复帧不稀释分母                        |
| 单通道最大差              | ≤64；q100为0                                           |
| 额外收益                  | 相比原件/严格无损较小者至少再省1%且1KiB                |

RMSE为黑/白背景下8位编码值误差，显示快照等权；没有假设播放器如何钳制零延时。时域量比较相邻显示画面的候选误差差值，包括第二轮首帧与上一轮最后显示帧；独立默认图不接入时间序列。原始分数逐字段相同，不以浮点时长近似代替语义检查。

v2保留v1全部门槛，增加实际子帧像素最低评分≥q，禁止用修正前或抖动前评分替代最终像素质量。score.rs按锁定imagequant 4.4.1的gamma=0.57内部颜色空间、alpha预乘/通道权重、黑白背景最坏距离与质量映射标量公式改编，使用公共固定色表API对照测试，完整COPYRIGHT随源码及报告保留。它仍是编码器相关误差尺度，不是人眼质量认证。

报告列出remapping_below_target、actual_pixels_below_target、alpha_palette_unavailable、alpha_class_changed、alpha_error等原因，并分别记录原始alpha与原始/合成总体误差。连续OVER可能累积误差：原始差≤4不保证合成差≤8；必须继续拒绝超过总体门槛的候选。实验q100仍生成索引候选，可能改变隐藏RGB和表示，不能标成生产严格无损；生产q100直接使用O1严格无损。Options新增remapping/maxPaletteSearches，默认alpha_palette；实验报告policyVersion升为2，旧v1候选字节对照须显式选择standard，实际评分和新版门槛仍按v2执行。生产请求/报告迁移见核心说明。

## 工作预算与取消

基础Limits沿用验证器的可收紧上限：输入/候选各16MiB，画布/单帧4Mi像素，256帧、4096块、1MiB元数据，64Mi累计像素工作，512MiB累计解码工作，128MiB验证缓冲估算。量化、重映射和源/候选比较共用同一累计账本；采样、alpha统计/组内量化、约束重映射、实际评分、alpha检查、画布合成/复制/清除及双背景遍历计费。每次子帧解码按25 bytes/像素保守计入严格zlib与双解码工作。额外色表条目检查最多64Mi次（含256个alpha可行集合预计算），超额明确报palette_search_budget，缓存命中不重复收费；0额度可确定性拒绝。

设C为画布像素、P为最大子帧/独立默认图像素、I为输入字节、O为最大候选字节、S为样本上限、F为帧数：

- 工作集估算：96C+128P+4(I+O)+256S+33MiB，默认上限512MiB；新增1MiB覆盖分组统计/代表色、可行集合和有界缓存。
- 验证存活估算：64C+48P+3(I+O)+8192F+1MiB，受128MiB上限约束。

结构解析后、首次解码前准入；运行中逐步计费且所有额度同时生效。生产复用时延续源/无损基线已消耗的累计额度，并在上述存活估算中加上仍持有的基线和源摘要；落盘复验继续同一账本。PNG临时候选写入有长度上限，最终APNG每个chunk追加前复查候选上限。估算包含向量容量/解码/量化scratch与原生余量，不能当作分配器或进程RSS硬配额。

总协作期限默认10秒。imagequant量化/重映射进度回调检查取消和期限；png编解码内部同步调用返回后再检查，调用方须持有资源直到整个函数返回。实验程序10ms采样进程工作集与CPU，包含采样器，不证明未采到的峰值或硬实时。CLI的执行中取消和1ms期限另留真实返回耗时。

## 当前结论与下一步

2026-10-15本机v2矩阵显示：分组色表消除了当前语料的原始alpha分类变化，覆盖全部实际alpha；沙滩球q80由原始差27降至4，但实际像素评分74及单通道误差仍拒绝，约25KB候选不能算合格输出。棕褐色照片衍生动画在q80/q95通过质量和相对O1的额外收益；复杂半透明和连续OVER仍有明确拒绝。这是算法边界，不降低现有质量门槛来凑通过率。具体最终数据、命令、浏览器/人工边界与三平台状态见[连续记录](../../docs/devlog/_plan/261009/animation-foundation.md)。

单文件候选选择、质量/收益回退和安全提交已接入，pnpm apng:core:check独立保留生产模式证据。下一步完成人工观感复核，再接批量预算、实际报告和桌面；三平台按新SHA单独验收。不满足质量的半透明/连续OVER候选继续回退严格无损；误差驱动的色表分配及更保守alpha表示可作为后续算法优化，不靠放宽门槛扩大支持。Windows本机结果不替代macOS/Linux CI与人工动画观感。

参考：W3C PNG第三版的8位索引、PLTE/tRNS、APNG默认图/帧控制规则；锁定imagequant 4.4.1的Histogram::quantize冻结色表实现。旧png-palettes只作只读算法参考，本轮没有修改。

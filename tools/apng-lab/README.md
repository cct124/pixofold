# APNG严格无损实验（A1/A2）

这是开发语料与内存编码实验。A3已将验证器迁入[APNG核心](../../crates/pixofold-core/src/apng/README.md)，实验复用其入口；A4将内建APNG接入批量预算、v13四格式工作台及受限首帧预览，静态PNG路径继续拒绝动画。实验通过与生产/GUI/安装验收分别记录。

## 可复现入口

在仓库根目录使用已锁定的Rust、Node与pnpm：

```powershell
pnpm apng:fixtures:generate
pnpm apng:fixtures:check
cargo test -p pixofold-core --locked --test apng_lab
pnpm apng:lab:check
```

- 生成器为本项目独立编写的PNG/APNG容器和存储DEFLATE编码器，固定CRC、Adler32、序号和数据。清单固定原件SHA256、结构/默认图参与规则、原始子帧与默认图摘要、手工给定的逐帧RGBA16画布及原始时间分数。
- 实验复制固定语料、6份既有公开原件、来源/许可至新的`target/apng-lab-*/`，另生成512×256×12帧压力图。运行前后校验输入SHA256，不覆盖仓库原件。合成语料故意冗余，收益不代表真实图片压缩率。
- 固定`png=0.18.1`、`oxipng=10.2.1`，后者关闭默认特性/内部并行。`fdeflate=0.3.7`复用png已锁定的同版本，A3已从开发引用提升为核心依赖，不升级任何依赖。`THIRD_PARTY_NOTICES.md`记录许可；公开图片继续遵循各自许可。
- O0/O1/O2全部关闭alpha优化、位深/色型/调色板/灰度缩减、16→8转换、交错变更、错误修复和元数据剥离。force仅用于保留较大候选供审阅，文件更小且复验通过才算gain。
- `report.json`记录每项输入/候选字节、哈希、gain/no_gain/rejected/validation_rejected、结构与播放摘要、耗时、CPU累计毫秒及进程工作集采样；`engine-identity.json`记录依赖、Cargo.lock/二进制/配方哈希、平台和工作树状态。全部候选保留在outputs；取消/到期候选丢弃。
- 验收必须与明确支持矩阵相符：接纳输入只允许gain或no_gain；公开低位深索引图只允许预定的unsupported_representation。新增编码/验证拒绝导致命令失败，不能靠记录“拒绝”就将实验标为通过。

## 独立验证与支持矩阵

容器解析与合成由[核心验证器](../../crates/pixofold-core/src/apng/validation/mod.rs)负责，原实验模块只作适配。png仅解码重建的静态子帧，不使用其APNG控制流程；oxipng不生成验证预期。

| 类别       | 本阶段范围                                                                                                                                                       |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 结构       | 签名按内容识别，支持.png/.apng及大小写；IHDR/acTL/fcTL/fdAT/IDAT/IEND顺序、CRC、连续序号、帧数、尺寸/偏移/边界、分块和截断均检查                                 |
| 默认静态图 | 参与或独立于动画均保留并比较原始像素；独立默认图不进入初始动画画布                                                                                               |
| 合成       | SOURCE/OVER、NONE/BACKGROUND/PREVIOUS、首帧PREVIOUS按BACKGROUND；局部帧、透明/半透明、隐藏RGB；RGBA16整数合成，不声称已完成显示器色彩管理                        |
| 时间与循环 | 原始delay_num/delay_den逐帧保持；分母0解释为100，分子0仍参与合成；num_plays为总播放次数、0无限。有限停止画面取最后显示帧；可重播时实际解码第二轮并从透明黑色开始 |
| 像素表示   | 灰度/RGB/灰度透明/RGBA的8/16位；8位索引及tRNS；保留原始位深、调色板、透明像素RGB。1/2/4位灰度/索引明确拒绝                                                       |
| 交错       | 保留Adam7；有4×4和局部帧人工语料，不转换交错方式                                                                                                                 |
| 元数据     | PLTE/tRNS、gAMA/cHRM/sRGB/pHYs/tEXt经长度/顺序检查并保持内容、相对次序及动画锚点；这不是ICC解释能力                                                              |
| 明确拒绝   | iCCP、eXIf、caBX、未知关键块，以及当前未列入白名单的元数据（包括sBIT/bKGD/压缩文本）；不剥离后继续、不降级为仅压缩默认图                                         |
| 比较       | 原始默认图、每个子帧、控制字段、精确分数、元数据和每帧画布均一致。压缩块分片/序号重排后的连续编号可变；不做帧合并或时间分数等价化                                |

### 严格zlib与独立预期

png的兼容解码可能忽略zlib尾随字节或容忍缺校验尾。实验先用fdeflate核对完整流、Adler32及精确解压长度，再用png作原始/展开双解码。fdeflate本身有最多7字节预读，最后8字节逐字节输入以识别短尾随数据。负例覆盖缺尾、坏校验、多余解压字节、坏压缩流和非法调色板索引。

清单中的小图画布不由验证器计算；如128/255透明蓝叠加同透明度红，规范RGBA16预期为`[21788,0,43747,49279]`。原始像素摘要来自生成器明文输入；Adam7输入按正常行序列给出预期，验证解交错而非复用编码器输出。

## 资源、取消与生产边界

| 额度                      | 默认上限                                                                             |
| ------------------------- | ------------------------------------------------------------------------------------ |
| 输入 / 候选               | 各16 MiB                                                                             |
| 画布 / 单帧               | 各4 Mi像素                                                                           |
| 累计像素                  | 64 Mi像素，包含独立默认图与实际第二轮解码                                            |
| 累计解码工作              | 512 MiB，包含严格zlib及原始/展开双解码，16位按两字节计费                             |
| 帧 / chunk                | 256 / 4096                                                                           |
| 元数据                    | 1 MiB（含chunk开销）                                                                 |
| 验证存活缓冲估算          | 128 MiB：双画布、子帧、解码scratch、重建流、两份比较输入、摘要与余量；超过则提前拒绝 |
| 验证协作期限 / 编码软期限 | 各10秒；压力实验另测1ms编码期限与编码中取消                                          |

所有额度只允许收紧。验证阶段在块/帧/行/解压分段处检查取消和期限；单次png解码等内部调用需返回后才能检查。整数额度控制可见分配与工作，不是进程RSS硬上限。

oxipng当前同步入口无取消回调，timeout用于跳过后续优化，不承诺立即终止。实验取消后等待编码真实返回，再丢弃候选；内存采样覆盖整个读取/验证/编码过程，10ms周期加起止采样，CPU包含采样器自身，不能证明未采到的峰值或硬隔离。A3必须保持相同worker/资源许可直到同步编码返回；如要求强制时间或RSS上限，先引入受限子进程并验证回收，不能以停止等待代替停止运算。

Windows结果表明公开素材收益较小且因预设而异，许多样本无收益。A3单文件核心采用固定O1、落盘复验及无收益保留原图，不自动搜索多档。A1/A2的8b89bba三平台APNG实验已通过；A3新代码须独立验收。最终本机数据、命令及CI状态见[连续记录](../../docs/devlog/_plan/261009/animation-foundation.md)。

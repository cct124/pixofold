# PixoFold（轻图）UI 交互与质量映射设计

更新日期：2026-09-29。状态：设计规范，已有HTML交互原型；静态PNG工作台已接通原生文件/目录选择与受控拖放、真实任务/扫描反馈分页、设置、重试/清除及汇总，P5新增指定输出目录与可选保留结构。启动后不提供用户主动取消功能，底层退出收尾不变。缩略图和其他格式未开放；P5原生GUI仍待用户手测，实际验收范围见开发记录。本文与 [项目方案](pixofold-proposal.md) 配套，覆盖界面布局、亮暗主题、0–100连续质量滑块及精细输入。

交互参考：[PixoFold HTML 原型](../UI界面设计/PixoFold.html) · [运行与修改说明](../UI界面设计/HTML原型说明.md)。原型默认展示空的导入识别区，拖入或选择文件/文件夹后自动模拟压缩；可在关于中主动导入示例。压缩进度与结果为演示数据，实际产品仍按本文要求使用真实任务状态。

## 设计依据与范围

- 参考 png-palettes 的左侧导入工作区和右侧设置栏，保留用户已有的操作习惯。
- 界面采用现代桌面工具的简洁布局；高级选项常显、不折叠，许可信息放入关于界面。
- 首版覆盖 PNG、JPEG（`.jpg` / `.jpeg`）、GIF、APNG；这些格式在有损模式下共用质量控件。未来格式接入同一质量意图层，增加各自的映射实现。
- 亮色与暗色使用相同布局、控件顺序和任务数据；设计图与原始参考图存放在 [UI 界面设计目录](../UI界面设计/README.md)。

## 界面布局

以约 1600×1000 的桌面窗口为设计基准，左侧工作区约占 70%，右侧设置栏约占 30%。实际界面采用弹性布局，右栏建议宽 360–440 CSS px；窗口最小约 1080×720 CSS px。空间不足时让列表和设置区域独立滚动，保持标题和当前质量描述完整可读。

滚动区域始终预留滚动条占位，切换「另存副本」或列表增长时，不因滚动条出现而改变内容宽度。滚动条采用 6px 细条、透明轨道和圆角滑块，隐藏上下箭头；亮色滑块不透明度为 24%，暗色为 22%，悬停时分别提升到 42% / 40%。不支持自定义滚动条的浏览器使用细滚动条回退样式；滚轮、触控与键盘滚动保持原生行为。

| 区域 | 内容与行为 |
| --- | --- |
| 标题栏 | 显示 `PixoFold · 轻图`；右侧为浅色/深色切换、最小化、最大化和关闭；交互按钮不参与拖动窗口 |
| 左侧中央识别区 | 空闲时显示大面积虚线拖拽框、图片图标、支持格式及「选择文件」「选择目录」；导入完成自动开始处理并切换为图片列表 |
| 图片列表 | 占用原识别区，展示全部图片的缩略图、文件名/相对路径、压缩前后大小、减少比例和状态；当前处理行显示单文件进度，完成后保留结果；列表独立滚动 |
| 底部提示与汇总 | 桌面端至少约 170 CSS px；无有效图片时显示操作技巧，有图片时显示总文件数、原始总体积、当前总体积、累计节省空间与比例、各状态数量、总进度条和批次操作，不随列表滚动 |
| 右侧设置栏 | 有损/无损模式、质量滑块、下方精细数值、输出设置、始终展开的高级选项 |
| 主要操作 | 拖入或选择文件即触发处理，不显示独立开始压缩按钮；无有效文件或参数未通过校验时不启动；扫描/准备/处理中不提供主动取消，结束后可重试未完成文件、清除结果或导入下一批 |
| 辅助操作 | 语言和关于入口保持低视觉权重；左下显示文件计数与总大小 |

输出设置使用与压缩设置一致的分段切换控件，顺序为「原图覆盖 / 另存副本」，初次使用或重置设置时默认选择「原图覆盖」，正常重启恢复用户上次选择。原图覆盖时隐藏输出目录区，在常显高级选项中展示「覆盖前备份原图」，默认不勾选（旧配置缺失/非法值同样为false），重启恢复有效选择。未勾选不生成备份，勾选才在同目录备份后覆盖；无收益均保留原图、不备份。副本模式隐藏且忽略备份开关，切回覆盖恢复选择。任务启动时固定输出与备份策略，普通重试沿用原行策略，不因运行中修改草稿改变。

选择「另存副本」后，在切换控件下方显示「输出目录」标签及「原文件夹 / 选择输出目录」控件。副本保留完整原文件名，不加后缀；未指定目录时提示“同目录会与原图重名，请选择其他输出目录”，不得静默覆盖。通过原生对话框选择已存在的目录，显示安全末级名称并允许「恢复原文件夹」；不提供路径文本输入。指定目录时才显示「保留输入目录结构」，默认不勾选；只拒绝实际冲突的图片，其余继续，不提供自动编号或覆盖已有副本。

切换覆盖/副本在当前连接保留已选目录。仅持久化指定目录意图及布局布尔值，不保存目录路径或授权ID；重启/重连后明确要求重选，缺少目录时新导入只扫描、不压缩，不能静默回退原文件夹。取消选择保留原草稿，明确的无效目录响应提示重新选择；Ready清单可在不重扫的情况下修正目录后启动。运行中选择只改下一次设置；普通重试使用原任务目标，不要求为新草稿重选目录。

初始空状态展示中央导入引导，底部显示批量导入、先设置参数及快捷操作技巧，隐藏零值统计与空进度条。拖拽文件、拖拽目录、选择文件和选择目录共用导入入口，目录递归扫描子目录，完成格式识别与本批去重后自动启动。有效图片进入列表后，识别区切换为全部文件的明细列表，底部切换为汇总；桌面端保持底部容器高度与位置，窄屏允许文字与操作换行。处理期间不提供取消、清除或新批次导入；终态后，可直接导入下一批并替换上次列表及汇总。

底部根据是否存在有效图片切换视图：参数待修正、处理中、已完成或已取消时均保留汇总，清除结果后恢复技巧。没有支持的图片时继续显示技巧，并保留识别结果与失败原因；扫描阶段显示扫描状态，避免技巧遮蔽导入反馈。

运行中在列表逐行展示真实阶段/百分比、原始大小、输出大小和减少比例，底部实时汇总「完成 / 无收益 / 失败」数量和体积变化；底层安全收尾产生非零取消计数时仍如实展示。重试按钮称为「重试本页未完成项」，只选择失败或取消行，单个文件失败不阻止其他文件继续执行。中断不自动重启；重试作为新的启动操作固定当时设置。只有成功完成项计入节省量，待处理、处理中、失败、取消和无收益文件均按原始大小计入当前总体积，避免虚报收益。

原生文件/目录选择框的取消仍保留，返回空选择不创建任务；参数待修正的Ready清单仍可清除。移除用户取消操作不删除内部取消令牌、取消终态或输出层提交前复查；关闭窗口仍停止接纳并等待编码真实返回、清理临时文件和线程收尾，已经提交的成功结果不回滚。桌面任务协议v2删除cancel变更及页面控制器入口，旧版本取消请求拒绝；前后端须使用同一构建。

总进度按全部文件等权聚合：完成、失败与无收益文件计为已处理，当前文件采用阶段百分比，待处理文件计 0；100% 代表本轮处理结束，成功率由状态计数单独表达。取消保留已完成结果与中断进度，重试仅重置未完成项的进度，因此总进度可能回退。正式编码器无法提供百分比时展示阶段信息，不伪造单文件进度。

桌面端列表与设置栏独立滚动，底部汇总保持可见；窄屏列表使用卡片排列保留完整字段。行更新不重建整个列表或重置滚动位置。缩略图按需加载；原型的本地预览 URL 在清除、替换批次和关闭时释放，正式版本采用受限资源访问及缩略图缓存。

参数无效时保留本次识别结果并显示等待修正，参数恢复有效后自动开始。空目录、没有支持格式或全部读取失败时只显示识别反馈，不创建压缩批次。去重限于本次导入，允许重复导入同一文件验证不同设置。HTML 文件识别仅检查签名和有限头部信息，正式后端继续承担完整解码校验、文件授权和可靠输出。

### PNG 首个桌面闭环的导入约束

以下为P2核心已确定、现由P3/P4/P5接入桌面的契约；HTML原型本身仍不执行真实压缩：

- 当前可处理列表只展示静态 PNG，不将 JPEG/GIF/APNG 等规划格式冒充可用能力。按内容而非扩展名识别；扫描反馈区分不支持、损坏/读取失败、重复项和保留产物排除。扫描只验证 PNG 结构与 CRC，完整像素解码仍可能在处理阶段失败。
- 扫描阶段显示发现/检查/接受数量和已读取字节，不显示编造的耗时百分比。扫描取消或触及数量、深度、读取预算时保留部分反馈，但不自动开始压缩；提示缩小导入范围或调整允许的限制后重新扫描，不能通过改参数把部分清单当完整批次启动。
- 只有完整扫描且参数与输出预检通过才自动启动。参数/目标预检失败时保留本次候选，允许修正后重新规划；没有候选不建批次。扫描、规划和压缩应共用单个应用级接纳门闩，期间不叠加新导入；窗口重载不解除后台所有权。
- 副本保留原文件名（扩展名、大小写不变），指定目录扁平布局直接放副本，保留结构时为 `目标/导入根名/相对父目录/原文件名`，单独选择的文件直接放目标根。同名根可合并布局，目标已存在、同批目标重名/父子冲突或输出与输入冲突只让相关副本行失败，其他图片照常处理。同目录副本必然冲突。完成列表展示逐项错误；解决目标占用后重试失败项，普通重试沿用原目标，不重新执行成功项；需要换目录则重新导入，不暗中覆盖或整批退回Ready。
- 默认排除核心保留名的临时/备份文件，明确展示排除原因；这不是文件来源证明，恰好同名的用户文件也可能排除，不能笼统过滤所有隐藏文件或 `_compressed`。自动生成的备份必须继续可定位，不自动回收。
- 输出先等扫描结束；新结构目录由输出层按需创建。取消/失败/无收益不留下临时文件（清理失败需明确报告），但可能保留空结构目录，不能以空目录存在就宣称压缩成功。

详细资源默认值、保留名与 API 边界见 [README](../../README.md)；原生文件授权、重订阅恢复和真实窗口验收见 [批量桌面计划](../devlog/_plan/260922/png-batch-desktop.md)。

P3a应用所有者与P3b订阅所有者已接入桌面生命周期，P4工作台已使用页面唯一订阅适配器。界面显示“正在取消/等待当前编码返回”或退出阶段，关闭期间禁止新导入或重复启动，不能把等待超时或窗口卸载当作编码已停止。完成清单等待参数修正时仍占导入门闩，可清除后重新导入。批次全取消后的应用协调状态为Finished，界面读取核心计数和逐行结果，不按外层枚举显示“全部成功”。处理中的原生关闭与窗口重载仍需单独验收，不以mock或空闲启动代替。

订阅错误应保留最后好快照并标记连接异常，不能伪造新进度。已知会话先完成disconnect再connect恢复；若首次响应失败导致会话归属未知，适配器会报告reload_required，UI需明确提示重载，而不是无限重试或悄悄累积监听。重载只恢复显示，不重跑任务；正式UI需在原生WebView中验证此路径。

工作台复用原生选择/操作适配：先connect完成首次快照/ACK，选择期间固定设置；取消原生选择不建任务，关闭/重载后的迟到结果不能自动启动。传输不确定先恢复快照再由用户决定，不能从展示名拼路径。模式支持无损/有损，输出接通覆盖、同目录及指定目录副本；输入/输出选择共享物理对话框互斥但授权用途分离。拖放在空闲时通过同一导入授权/扫描链路接纳，规则见下节。重试限定同revision当前页的失败/取消行，使用稳定ID、当前批次revision和有效草稿模式/质量，沿用原行输出目标；传输不确定不自动重发。清除前确认并展示需保留的恢复信息，清除不删除备份或结果文件。

当前工作台每页50行，状态变化或stale_snapshot回到首屏，不保留全量列表或跨revision拼页；底部显示真实processed/total及成功、无收益、失败、取消计数，未知字节为“—”。只显示阶段不伪造编码百分比；外层Finished不表示全部成功。结果列标明实际回退原因、输出/备份及恢复临时文件显示名。页面加载恢复Ready不自动重跑，需主动调整设置；本页非法质量导入后修正则自动启动一次，后台规划失败后同设置不无限重试。主题和语言切换不重新订阅。

main页面Started由Rust主动撤销旧订阅及未消费授权，物理对话框仍占槽直到实际返回；不取消/重建任务。前端最后观察者释放后清理连接，StrictMode同步重挂载复用连接；异步清理未完成时新挂载等待，不依赖卸载取消后台计算。

### 原生拖放导入（协议v5）

- 左侧图片区域（空态或已结束列表）接纳文件和文件夹，目录递归、重复根、非图片和错误反馈复用真实扫描器；拖到设置区、标题栏或区域外不导入，不自动导航打开文件。
- 后台只在空闲/已结束时为同一原生Enter/Drop手势发放单次授权；页面必须完成首次快照/ACK。终点坐标以当前DPI换算并命中可见区域，任何弹窗打开、页面隐藏、正在操作或需要恢复时不启动新批次；忙时不缓存下一批自动处理。
- 拖放接收时冻结当前模式/质量/输出；非法质量只扫描，修正后自动开始。结束后的新拖放是新批次，不向运行中的任务追加，不清理历史输出/备份。
- 只经Rust原生事件取得路径；前端接收票据和坐标，不接收/上传路径或图片字节。拒绝/消费之后释放票据，重复、旧会话、离开或重载不能触发重复写入；传输失败先恢复，不自动重试。
- 首版保留静态拖入提示，不发送高频Over/实现原生悬停动画，避免UI阻塞时积压通知。浏览器预览不具备文件授权。原生OS、多DPI/缩放、亮暗/中英与窄窗验收另记，不以模拟事件证明通过。

### 内容凭据问题图片的显式处理（v4引入，v7扩展指定目录）

- 普通RGB正常压缩；只有完整解码与全部元数据检查通过、唯一不支持类别为caBX的失败行可以确认移除。混合其他未知保护块、损坏、真正验证失败、清理失败不提供跳过检查的选项。
- 正常图片继续完成，本页面观察到任务结束后统一弹出一次列表。重新加载已有终态不抢焦点；关闭/暂不处理不写文件，可从“需要确认的图片（总数）”重开。开始处理后无主动取消。
- 说明精简为“这些图片含内容凭据，压缩需将其移除。原图尚未修改。”表格显示文件名、安全来源标签、稳定任务ID、原因与移除影响；不分页、限高滚动、默认全选，可全不选或取消单项。后台仍按同revision顺序分段取齐全部行，完整加载前禁提交；中途失败或版本变化丢弃旧列表，重新加载默认全选。
- 打开弹窗固定当前模式/质量/输出草稿，无损注明“仅像素无损”。当前选“另存副本”时不显示备份模块，沿用该次草稿的同目录或指定目录及结构策略，保留原文件名，目标冲突只拒绝对应图片，其余选中图片继续；缺少有效目录/质量时提示关闭弹窗修正后重开。当前选“原图覆盖”时才显示“覆盖原图 / 备份原图”，初值继承主设置备份开关。只对所选凭据行重规划，不移动或重跑已完成普通图片。
- “覆盖原图”明确提示直接覆盖、不保留备份；“备份原图”在同目录保存完整原文件后覆盖，备份名随结果返回。弹窗标明仅对本次选中图片生效，不追溯改变已完成普通图片或主设置。普通导入与确认流程都支持有/无备份；所有输出仍经过校验和提交前复查，无先删后写路径，普通重试不继承移除凭据许可。
- 普通与凭据图片共用备份命名：`<原文件名，不含扩展名>-backup-<6位ASCII字母数字随机标识>.png`。完整原名不截断、不替换非Unicode字符；过长导致创建失败时保留原图。结果详情/提交失败恢复信息显示实际备份名，日志不记录该名称；扫描继续排除新旧备份，旧文件不自动重命名。
- 删除独立同意勾选模块，点击“移除内容凭据后压缩（数量）”即同意本次所选行及输出方式；关闭不授权，不称“强制覆盖”。不验证真实性、不更新/重新签名，不提供默认永久授权。
- Rust保存失败源版本（绝对路径、属性和SHA256），确认操作受会话、selection和批次revision约束，后台编码前复验；路径和摘要不传给页面。剥除仅作用内存工作副本，备份与提交前检查以完整原文件为准，只移除caBX。
- 错误、目标冲突或无收益不覆盖源文件。成功结果明确标记“已移除内容凭据”；普通重试不会继承上次许可，参数修正也不是移除同意。断线或响应未知时只恢复快照，不能自动重发写操作。

## 连续质量滑块与数值联动

统一质量值记为 `q`，有效域是整数 `[0, 100]`。q 越大，表示越倾向保留画质；不代表越省空间，也不是不同格式共享的客观感知评分。初次使用或重置质量时取 `q = 80`，描述为「高」。正常重启恢复用户上次有效设置。

| 质量描述 | 数值区间 |
| --- | --- |
| 低 | 0–29 |
| 较低 | 30–49 |
| 中 | 50–69 |
| 高 | 70–84 |
| 较高 | 85–94 |
| 最高 | 95–100 |

滑块是 0–100 的线性连续轨道，按整数逐值调整，不吸附到六个预设位置；轨道没有档位圆点，下方不再排列「低、较低」等标签。仅在「压缩质量」标题行右侧显示当前描述，位置与原设计一致，去掉描述的边框和背景。输入框位于滑块下方，标题「精细调整」，显式标明范围 `0–100`；默认内容为 `80`，滑块拇指停在轨道 80% 的位置。

联动规则：

1. 点击轨道或拖动滑块时直接写入对应的 0–100 整数，输入框同步更新；保留诸如 17、73、96 等非预设值。
2. 输入框接受任意 0–100 整数，输入有效时即时更新 q 和滑块位置。质量描述按上表区间派生，描述切换边界为 30、50、70、85、95。
3. 输入 76 时实际 q 保持 76，滑块位于 76%，当前描述显示「高」；描述只用于展示，不反向覆盖数值。
4. 输入期间允许临时为空，但空值、负数、大于 100、小数和非数值文本均不能进入后端参数。显示「请输入 0–100 的整数」，暂停自动启动并保留已识别文件；修正后自动开始，按 Escape 恢复上一次有效值。不要静默截断、四舍五入或截取越界值。
5. 滑块键盘左右键每次加减 1，Home/End 选择 0/100；数值框上下键以 1 递增或递减，并限制在有效边界。
6. 混合格式批次使用同一 q。每个任务按识别出的真实格式解析参数，不根据文件后缀强行选择错误的编码器。

「数值越高，画质保留越多」作为简短帮助文案；100 仅表示当前有损质量尺度的最高设置，不能自动标为无损或保证文件最小。

## 有损、无损与高级选项

主界面仅保留「有损压缩 / 无损优化」两种模式，默认有损。取消原来与质量重叠的「均衡压缩 / 体积优先」预设入口；用连续质量值及其文字描述表达画质取舍。

切换为无损模式后，保留质量区的位置但禁用滑块和输入框，提示「无损模式保留原始画质」。后端收到的是无损模式参数，不附带有损 q。前端单独记住最近的有效有损 q，切回时恢复，不重置为默认值。

高级选项中的计算强度、imagequant 速度、抖动、JPEG 色度采样与元数据策略不借用品质滑块。默认主界面不直接展示 `minimum/target`、Gifsicle `lossiness` 等原生字段；尤其不再提供一个可独立改写 q 的第二个目标质量输入。

## 各格式的参数映射

由 Rust 核心的 `quality` 模块解析 q，前端不拼装原生编码器参数。下面是映射版本 `1` 的设计候选，需在基线阶段实测和校准；表中数值不是各库提供的统一质量标准。

| 格式与模式 | 版本 1 候选映射 | 独立约束 |
| --- | --- | --- |
| PNG 有损 | imagequant `set_quality(0, q)`，目标取 q，最低阈值默认 0 | 调色板生成后按原有输出与质量检查决定是否提交；速度、抖动独立配置 |
| APNG 有损 | 与 PNG 共用质量映射，按当前动画的帧数据生成共享调色板 | 保持帧时长、blend/dispose、透明和合成效果；未通过动画回归时明确跳过有损处理，不退化为静态图 |
| JPEG 有损 | MozJPEG 原生质量暂定 `max(1, q)` | 界面 0 映射到编码器最低采用值 1；色度采样、渐进式、ICC 与方向处理独立；100 不等于像素无损 |
| GIF 有损 | q 反向映射到 Gifsicle lossiness，见下表 | q 越高允许的误差越少；不随 q 自动缩放、降帧或改变时间轴 |
| 各格式无损 | 不使用 q；分别走 oxipng、jpegtran、Gifsicle 无损优化等路径 | 各格式无损不变量按项目方案验证 |

GIF 候选锚点如下；在相邻 q 锚点间线性插值并四舍五入为非负整数。q = 100 时省略 `--lossy` 选项，不能传一个没有数值的 `--lossy` 而触发工具默认误差。版本 1 不额外随 q 减少颜色数，避免叠加未校准的画质变化。

| q | 0 | 20 | 40 | 60 | 80（默认） | 90 | 100 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Gifsicle lossiness | 300 | 200 | 120 | 60 | 30 | 10 | 0（省略选项） |

必须验证映射方向和范围；图片的实际体积、感知画质不保证严格单调。若 q 未达预期或输出无收益，按结果验证与回退策略处理。编码器不支持的输入不能静默丢失位深、色彩信息或动画。

imagequant 官方定义了 0–100 目标质量；Gifsicle 的 lossiness 则是数值越大允许越多误差。统一的 UI 尺度在本项目内部转换，不把 q 直接作为所有库的同名参数。MozJPEG 的 quality 经 Rust 包装调用底层 JPEG 质量设置，使用前需完成会重置参数的默认配置。[imagequant 质量接口](https://docs.rs/imagequant/latest/imagequant/struct.Attributes.html#method.set_quality)、[Gifsicle 参数说明](https://www.lcdf.org/gifsicle/man.html)、[MozJPEG Rust 质量接口](https://github.com/kornelski/mozjpeg-rust/blob/master/src/compress.rs)

## 状态、IPC 与持久化

| 层 | 职责 |
| --- | --- |
| `QualityControl` | 只通过数值和变更回调对接 store；用映射表派生档位；独立保存输入中的暂态字符串和错误提示 |
| 前端设置 store | 保存压缩模式、最近有效有损 q、计算强度、输出策略与主题偏好；不持有第二套独立档位值 |
| Rust `QualityValue` | 只接受 0–100 整数；IPC 与磁盘配置均需验证，不能仅依赖前端输入控件 |
| Rust `quality` 模块 | 根据格式、q 和映射版本生成原生参数；参数超界或不支持时返回结构化错误 |
| 批次与任务快照 | 固定本次 q、映射版本、编码器版本、解析后的格式参数和输出策略；修改界面只作用于下一次提交 |
| 配置持久化 | 使用带 `schemaVersion` 的配置保存最近设置；首次使用取有损 q = 80；损坏配置回退有效默认值并保留可诊断信息 |

推荐请求模型使用判别联合：有损模式为 `{ kind: "lossy", quality: 80 }`，无损模式为 `{ kind: "lossless" }`；批次另带 `qualityMappingVersion: 1`、计算强度与输出选项。档位标签是展示派生值，不作为需要后端同步的第二个质量字段。最终 DTO 由 Rust 类型生成 TypeScript 声明。

目标输出模型区分覆盖及副本；当前静态PNG桌面协议v7保留`overwrite`（备份覆盖）/`overwrite_without_backup`/`copy_beside`，新增`{ copy_to: { directoryId, preserveStructure } }`，不接收路径。设置层保存输出模式及严格布尔值`backupBeforeOverwrite`、`customOutput`、`preserveStructure`，提交副本忽略备份草稿；后两项不替代当前会话原生目录授权。启动后固定本批输出与目录身份，运行中切换仅影响后续任务，普通重试保留原行目标/备份策略。旧配置模式缺失/非法则覆盖，布尔值缺失/非法则false；旧协议须更新重载。

从旧配置迁移时，合法的 PNG `qualityTarget` 可作为最近有损 q；未找到旧值时默认 80。旧的速度和抖动迁入高级设置，旧 `qualityMinimum` 不自动覆盖统一 q。仅读取确定的配置结构，不把无关 localStorage 数据视为项目设置。

## 亮暗主题与可访问性

初次启动跟随系统亮暗偏好；显式选择后持久化，后续启动优先使用已保存的选择。选择「跟随系统」可放入设置页面，主标题栏的浅色/深色切换仅显示太阳/月亮图标，不显示常驻文案；保留选中态、随界面语言更新的悬停提示和无障碍标签，窄窗口仍显示两个图标。

## 验收条件

- 实现显示「PixoFold · 轻图」；质量控件为连续轨道，没有档位圆点和下方标签；当前描述显示在标题行右侧，无边框和背景；默认数值为 80。
- 滑块可到达 0–100 的每个整数；输入的 0、29、30、49、50、69、70、84、85、94、95、100 对应正确描述；输入 76 时滑块同步到 76%，不被回写成 80。
- 非整数和越界输入不会进入任务请求；参数无效时等待修正，恢复有效后自动启动；键盘操作可完成所有质量设置。
- 空闲时显示识别区，导入后切换为全部图片列表，不显示手动开始按钮；文件和目录的选择/拖入均自动处理，递归扫描、重复/非支持文件、读取失败和空目录均有明确反馈。
- 每行显示压缩前后大小、减少比例和状态；底部总进度与数量、总体积、累计节省量实时一致，滚动长列表时汇总保持可见；失败与未处理文件不计入节省量。
- 无图片时底部显示操作技巧，隐藏统计与进度；有有效图片后显示汇总，完成或取消后保留，清除后恢复技巧；无支持文件的反馈仍可见，桌面端切换不改变底部高度与位置。
- 中英界面在扫描/准备/压缩阶段均无主动取消入口，Escape不取消批次，运行中更改设置不写入当前批次；旧cancel IPC被拒绝。底层中断不会自动重启，重试与下一批导入按规则更新快照；清除非活动记录恢复空状态，页面重载仅恢复权威快照。
- 四种格式与混合批次接受同一质量意图，各自映射为正确方向和范围的原生参数；任务日志可还原本次映射版本。
- 无损模式不执行有损映射，切换模式后可恢复最近有损 q；最高档不冒充所有格式的无损。
- 输出设置默认选中原图覆盖且不显示目录控件；另存副本展开原有目录控件，往返切换保留已选目录；模式持久化、重置和批次快照保持一致，覆盖批次不应用副本目录选项。
- PNG/APNG 的透明边缘、JPEG 的色彩与采样、GIF 的动画合成和闪烁由图像语料验证；GIF 锚点未经实测不作为已达到的压缩效果宣传。
- 浅色/深色的布局、标签和任务内容保持一致；主题切换、界面重载和应用重启不意外清空质量设置或任务。
- 最小窗口下标题与当前质量描述仍完整可读；高 DPI、键盘焦点、禁用态、错误态和长文件名均有检查。

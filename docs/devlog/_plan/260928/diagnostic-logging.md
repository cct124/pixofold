## 目标与验收

- 开发构建固定写仓库logs/并通过/logs/排除；正式构建写系统temp_dir()/pixofold-logs/，不按版本或用户名拆目录。版本写每份日志头。
- JSONL，每次运行独立sessionId；含当前文件最多10份、每份不超过5,000,000 bytes，换文件保持sessionId。只清理本应用已关闭的旧日志，多实例不得删除活动日志；无可用槽位或写入失败时可观测降级，不阻断图片处理。
- 固定目录检查链接/目录类型及适用平台权限；不把完整私人路径、文件名、图片内容、凭据正文写入日志。日志是诊断信息，不是文件事务状态或授权来源。
- 有界后台写入，业务线程不写磁盘；记录启动资源、批次/任务/attempt、冻结策略、待确认/确认、备份创建/验证/保留、提交及结果，错误使用稳定类别。退出刷新并保留文件。
- 提供安全的日志状态及打开固定目录入口，不接受任意路径IPC。浏览器预览明确不可用，中文/英文和主题复用现有样式。
- 自动验证轮转/严格大小、并发活跃保护、JSON完整性、隐私、降级、结束刷新，以及真实PNG确认前无备份/确认后三种输出日志。正式构建和本机验证分别记录，不以模拟IPC冒充GUI或跨平台验证。

## 实施顺序

1. 核对现有依赖与退出所有权，建立脱敏结构化事件和有界写入器。
2. 实现固定目录、跨进程协调/活动文件保护及10份×5 MB轮转。
3. 接入核心pipeline、应用协调、确认接纳和输出事件，补测试。
4. 接入只读状态/固定目录打开及前端展示，检查契约、统一验证、构建。

## 关键决定

- 使用tracing记录核心事件并由桌面订阅，核心不依赖Tauri或日志文件。字段只允许受控标识/枚举/计数，队列满计数丢失，不同步阻塞编码。
- 文件数量与轮转需跨进程协调，而不仅是每实例各留10份；已锁定活动日志不能被其他实例清理。非日志协调文件不计入10份JSONL。
- 正式临时目录可能被系统清理；不承诺日志长期保留。创建失败不回退私人图片目录，也不擅自放宽权限。

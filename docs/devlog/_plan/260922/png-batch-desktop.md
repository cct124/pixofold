## 目标与当前判断

下一个产品里程碑是「首个真实可用的静态 PNG 批量桌面闭环」：选择或拖入文件/目录后，固定参数、后台处理、展示真实结果，允许取消和重试，继续保证失败/无收益不破坏原图。不是同时接入全部规划格式，也不是重新设计原型。

2026-09-22 代码复核：

- 核心已具备无损/有损单文件流水线、质量映射与保护性回退、有界输入/解码分配、可靠输出。pipeline::optimize_png仍是同步函数，只有阶段回调，没有批量状态或线程池。
- ResourceLimits限制单个输入/缓冲区，不是总RSS预算；简单按CPU核数并发启动大图不安全。

## 开发顺序与交付边界

### P0：收尾当前 PNG 引擎验收

1. 核实本轮CI三平台检查和桌面构建。失败时先归因并修复，不盲目重跑或降低测试标准；成功后在前序连续记录补证并归档。
2. 增补许可明确的真实素材和可复现边缘样本：截图/文字、渐变、抗锯齿透明图标、半透明阴影、16-bit及ICC输入。记录有损采用率、回退原因、体积和人工观感；不为提高采用率放宽alpha保护。素材不得来自未授权的私人图片。
3. CI运行期间可继续任务模型开发；三平台结果和代表性素材验收是PNG桌面里程碑交付门槛，不是无限期推迟纯逻辑开发的理由。

### P1：纯 Rust 批量任务服务（第一个开发任务）

先接受显式文件列表，暂不引入目录扫描、原生对话框和正式UI。复用现有pipeline，不另写编码/覆盖捷径。

- 定义BatchId、JobId、尝试次数/标识、不可变批次参数快照、批次/任务状态、稳定错误码、汇总和可查询快照。无损/有损继续使用现有PngMode；记录映射版本、输出策略与资源配置。
- 同一服务初版只运行一个活动批次；完成或真正取消后才接受新批次。参数草稿与运行快照分离，设置变化不能影响已排队项。
- 任务由Rust唯一持有，Queued → Running（真实阶段）→ 成功/无收益/失败/已取消；每个尝试恰好一个终态。取消请求不是终态，提交临界区实际成功时仍报告成功，不能把已写出的文件标成取消。
- 用有界队列与后台执行器调用同步pipeline；先以默认1个工作线程建立正确基线，测试可配置的并发上限。不上每文件一个无限spawn，不在同步锁内编码或I/O。
- 给已接纳任务数和活跃工作集设预算；工作集估算需包含原图快照、解码/RGBA、量化、候选/验证等同时存在的缓冲区，并为编码器内部内存留余量。预算不足时等待或给出明确超限结果，不死锁；估算不是OS硬限额。测量1/2并发峰值RSS后再决定提高默认并发。
- 为整批预先检查重复输入、输出重名和输出与其他输入的冲突；禁止同一源文件被两个worker同时覆盖。实际提交时仍保留output层的最终复查。
- 取消后未开始任务不执行，运行中进入取消中，等待计算/清理真正结束才释放槽位。清除结果、重试和退出不能误认为取消已完成。
- 重试仅针对失败/已取消项，按交互设计固定重试启动时的设置；成功/无收益项不自动重压。区分新的尝试与旧事件，保留已完成结果，拒绝旧事件覆盖新状态。

验收：无GUI的批量测试覆盖混合成功/失败/无收益、参数快照、并发上限、队列/内存预算、排队与运行取消、取消和提交竞争、重试、单项失败不阻断其余任务、资源释放及源图/备份安全。调度测试使用可控执行器/同步屏障，不依赖固定休眠；真实小批PNG回归验证服务确实调用pipeline。

### P2：统一导入与批量输出规划

- 文件、目录、后续原生拖放共用Rust导入入口；目录递归扫描，默认不跟随目录符号链接，限制文件数/深度并支持扫描取消。扫描进度独立于压缩进度。
- 结合规范化路径和文件身份做本批去重，处理重叠目录、大小写别名/硬链接；沿用现有核心对不安全链接输入的拒绝边界。坏文件、无权限目录、不支持格式可单项反馈，不中断整个导入。
- 根据内容识别静态PNG；JPEG/GIF/APNG明确反馈未支持，不静默处理APNG首帧，也不把错误扩展名当作唯一依据。导入预检保持有界，不能把全部图片完整解码后长期留在队列内存。
- 扫描先结束并冻结输入清单，再开始写输出，避免扫描到本批新产物；排除已识别的PixoFold临时/备份产物，不笼统排除用户合法图片。
- 副本默认原目录加_compressed后缀，另选目录时定义可重复的根目录/相对路径映射；多根目录重名、目标落入扫描树、输出与另一任务源文件重叠均预检。同名采用当前核心的拒绝策略，不静默覆盖；最终冲突仍由output层裁决。
- 默认原图覆盖和恢复备份不改变；UI应能明确看到备份位置或恢复提示，不增加未经验证的自动恢复/删除功能。

验收：嵌套目录、重复拖入/重叠根、空目录、取消对话框的空输入、扫描无权限、坏文件、生成产物排除、多根同名及目标冲突均可确定性测试。无有效文件不创建空压缩批次；参数无效时保留已识别清单，修正后才固定启动参数。

### P3：薄 Tauri 适配与真实桌面操作

- Commands仅适配导入、启动、查询/订阅、取消、重试和清除；服务生命周期属于应用，不属于React组件。仅按实际需要开放dialog、原生拖放、结果定位及缩略图访问，不授予通用shell或任意文件读写。
- P2完成后细化：应用级门闩覆盖扫描、等待参数/输出修正、规划和运行，阻止并行导入或重复自动启动；扫描在有界后台执行且有取消令牌，锁不跨I/O/await。保留完整ImportScan供修正设置，部分扫描只展示、不得启动；扫描在返回前释放身份句柄，返回完整结果后才接纳输出。
- Rust作为DTO权威来源，生成TS并增加契约测试；错误转换成稳定代码与必要上下文，duration/bytes明确单位和JS表示边界，不直接序列化底层Box错误。实际能力按格式/模式报告，只开放静态PNG，不把plannedFormats当作可用列表。
- 沿用方案的Channel+快照：先建立订阅再启动，事件包含批次/任务/尝试及单调序号；查询快照有版本，前端合并只接受更新版本，断线/重挂载能恢复，不丢终态或重复执行。
- 阶段事件按需合并，终态不被丢弃；无编码百分比时仅显示实际阶段/活动状态。总进度以已处理文件数为真实依据，失败/无收益也属于已处理；取消保留已完成进度，不因把排队项标取消就伪造100%。生命周期的终态数与用户进度数分开定义。
- 退出时明确取消并等待安全收尾/提交临界区，不能由前端卸载释放任务。窗口重载和应用退出分别定义；跨进程自动续跑/崩溃恢复不纳入本轮。若现有文档要求重启保存任务，需要在实现前明确本里程碑仅保存设置与展示记录、不自动重压，避免暗中承诺断点续跑。

验收：模拟IPC的契约/乱序/重订阅测试与Windows原生对话框/文件及目录拖放分别执行；界面重挂载不重启任务，前端断开时后台仍有明确所有者。

### P4：按既有原型形成正式 PNG 界面

- 直接增量实现正式组件，不另造要丢弃的演示页面：ImportArea、FileList、BatchSummary、QualityControl、OutputSettings。沿用已有主题、语言和布局，不重做视觉方案。
- 默认有损80、原图覆盖；导入完成且参数有效即启动，不添加开始按钮。运行中拒绝新批次；结束后可重试、清除或导入下一批。
- 配置store做版本迁移，持久化模式、最近有效q和输出偏好；输入框暂态/错误属于设置草稿，不传给Rust。切回无损不携带q，切回有损恢复上次q。
- 明细展示真实原始/最终大小、阶段/结果、回退原因和错误；只有成功项计节省量，其余按原始大小汇总。空列表技巧与固定汇总切换、独立滚动及主题/语言不重置任务按原型验收。
- 缩略图按需、有界缓存和受限访问；清除/换批释放资源，不通过IPC广播整批原图Base64。千级列表渲染压力与真实编码压测分开；视实测引入虚拟化。

验收：使用隔离目录进行Windows真实批量操作（含正常、损坏、已优化、透明/元数据回退、只读/冲突），检查覆盖备份、副本结构、取消/重试、统计、关闭与重开；另检查亮暗、中英、最小窗口、高DPI、键盘输入和长文件名。macOS/Linux编译测试与原生GUI验收分开陈述。

## 本里程碑明确不做

- JPEG、GIF/APNG/WebP，量化引擎替换、更多速度/抖动高级项。
- 多个并行批次、应用崩溃后自动续跑、云端上传、账户系统。
- 完整前后像素对比编辑器、自动备份回收/恢复、安装包签名与自动更新。
- 没有真实样本/RSS证据的激进并发或压缩率承诺。

保持现有crate边界，按职责增量加模块，不为未来四种格式预建庞大框架；只有实际复用/测试需要才抽象执行接口。前序引擎正确性缺陷仍优先修复。

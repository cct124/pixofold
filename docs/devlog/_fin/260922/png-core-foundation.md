## 目标与验收

完成第一个真实图片处理里程碑：给定一张静态 PNG，可执行无损优化，验证结果后按覆盖或副本策略提交；失败、取消和无收益均保持原图。通过独立 Rust 集成测试或开发用示例验证，不依赖 GUI。

计划创建时核心只有应用信息与规划格式，尚无扫描、编码、输出或任务服务。HTML 已明确交互，优先把真实处理与输出契约建立起来，后续界面可直接展示真实结果。

## 本任务实施范围

1. **建立可复现样本与基线。** 在 `tests/fixtures/` 保存自生成或许可明确的图片、来源与预期属性，先覆盖静态 PNG 的 RGB、RGBA、灰度、索引色、8/16-bit、透明边缘、显示元数据，以及损坏、已优化和伪造扩展名输入。按需提供生成脚本，避免依赖私人图片。记录环境、编码器版本、参数、输入/输出体积与耗时，不预设缩小比例。
2. **实现输入边界和最小模型。** 在核心 `model/`、`probe/` 定义图片信息、处理请求、输出策略、结构化错误和结果；检查真实文件格式、尺寸及资源限制，识别 APNG 并明确报告本阶段尚不支持，不能当作静态 PNG 处理。暂不创建第二套任务状态或为未接入格式堆叠抽象。
3. **接入 PNG 无损适配器。** 按方案验证 oxipng 的最新稳定兼容版本并锁定。质量值不进入无损编码路径；保持解码像素、位深、透明度及显示所需元数据，默认不修改完全透明像素的隐藏 RGB。先完成一次输入到临时产物的处理。
4. **实现可靠输出。** 在 `output/` 统一处理目标规划、独占临时文件、编码收尾、重新验证、最终体积比较、源文件变化检查、覆盖前备份及提交。同时实现原图覆盖和另存副本，同名目标按策略处理；不能先删除原图再写新文件。
5. **串联并形成验收证据。** 在 `pipeline/` 提供可独立调用的单文件入口，通过集成测试和开发用运行入口验证。结果返回真实大小、耗时和处理结论；编码器没有可用百分比时只报告阶段。把基线结果与失败处理证据补入本记录。

实现顺序为样本 → 最小模型/识别 → 编码临时产物 → 可靠提交 → 回归与报告。正式产品仍默认原图覆盖；开发验证使用隔离临时目录，覆盖路径必须通过验收。

### 实际改动与关键决策

- `model/compression.rs` 提供字节数、资源上限、PNG 描述、请求/输出策略、阶段、取消、报告及结构化错误；这些是暂不暴露至 IPC 的 Rust API。现有 AppInfo DTO 和 TypeScript 生成文件未变，桌面 `compressionAvailable` 保持 false。
- `probe/` 验证签名、完整 chunk 边界/CRC、IHDR、尺寸/像素/缓冲区上限与完整解码；扫描全部 chunk 拒绝 APNG，拒绝截断、尾随垃圾和伪装扩展名。解析使用 checked 运算及解码限额；文本与 ICC 不由探测器解压。
- `codecs/png.rs` 封装单线程 preset 1，30 秒为软期限（不是可抢占硬截止）；严格保留位深、色型、交错、隐藏 RGB。适配器只生成内存候选，不提交路径。
- `output/` 集中处理输入快照/句柄身份、目标规划、独占临时文件、flush/sync、重新打开、备份和提交。副本只支持“冲突即拒绝”；覆盖始终保留 `.pixofold-backup-*.png`，错误也暴露恢复路径。候选与备份在最后检查点再次逐字节校验，清理失败不静默吞掉。
- `pipeline::optimize_png` 同步编排真实处理阶段和墙钟耗时，失败/取消为 Result 错误，无收益不写最终文件。回调仅报告阶段；当前不引入线程池、任务 ID、IPC 进度或假百分比。
- 新增 `optimize_png` 显式输出策略示例、`png_baseline` 隔离基线、27 个自生成语料和来源/SHA256 清单；统一检查增加 `fixtures:check`。所有故障注入通过阶段回调，不使用固定休眠。

### 问题与修正

1. 基线最初在 indexed2 样本的元数据比较处失败。查 oxipng 10.2.1 源码确认：禁用 reduction 仍会裁掉 tRNS 的尾部不透明值并重排 chunk。改为仅采用优化后的 IDAT，重用原始非 IDAT 数据；重新解码后比对样本/位深/调色板/透明信息及全部非 IDAT 字节。未知 unsafe-to-copy 元数据（含 caBX/iDOT）拒绝，不复制可能失效的签名/偏移。
2. 加入源句柄身份复查后，Windows 覆盖测试出现 AccessDenied。最终身份检查后显式释放本进程持有的源句柄，再进入替换临界区；保留失败备份且不删除原文件的策略不变。外部程序禁止删除共享的占用仍明确失败，已回归。
3. 验证后产物及备份也可能被改动，补齐最后检查点的内容/句柄身份复查与故障用例；不能仅在编码刚结束时验证一次。
4. 只读源文件允许另存时不能给临时文件继承 Windows 只读标志，否则清理失败；覆盖仍拒绝只读原图，副本不继承只读属性。补齐该用例及 NTFS ADS/尾随字符别名拒绝。
5. 当前 shell 默认 Cargo offline，官方查询需显式联网授权；全局 pnpm 启动未返回，已中止，按 README 使用便携 Node 和精确版本 npm exec 执行。最初离线 npm 缓存缺失，授权后检查通过；未改变用户的全局默认工具链。
